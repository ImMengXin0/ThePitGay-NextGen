# Leaf TPS、读档与 NPC 右键补丁

输入为用户提供的 [spark 报告 ZztoNwIF0p](https://spark.lucko.me/ZztoNwIF0p)、17:45:30 玩家档案解析异常，以及 17:46 的重复实体 UUID 警告。环境为 Leaf `1.21.11-174-3727fcc`、Java 25、FancyNpcs `2.10.1-java21+2`。原始报告和完整服务端配置只保存在本地 `audit/`，没有提交到仓库。

## TPS 证据和修复

spark 采样持续约 639 秒，仅记录服务端主线程。报告统计显示：

| 指标 | 开始阶段 | 接近结束时 |
| --- | ---: | ---: |
| 已加载区块 | 15,882 | 61,172 |
| 方块实体 | 1,075 | 36,210 |
| 实体 | 990 | 2,123 |
| 时间窗口 TPS | 19.09 | 5.66 |
| 时间窗口 MSPT 中位数 | 17.00 ms | 168.88 ms |

最终平台统计为最近一分钟 TPS `5.14`、MSPT 均值 `195.22 ms`、堆内存 `7,731,155,392 / 8,589,934,592` 字节。多个中间窗口在线人数为 0，区块数仍持续增加。主线程调用树包含大量区块、随机方块、方块实体和普通实体 tick；不能把插件自身任务占比当作插件导致的全部间接开销。

源码中的 `ProtectListener` 在构造、世界加载以及每个 `ChunkLoadEvent` 中，把所有 Pit 区块加上本插件的永久区块票。区块票使已经访问的区块无法卸载；票导致相邻区块加载后，又会触发相同处理，形成继续向外加载并保留的路径。这与无人在线时区块仍扩张的报告相符。

本次删除这些无界区块票。玩家附近区块由服务端正常管理；NPC 已有区块加载/卸载时的自动隐藏与恢复逻辑，金锭选择器只选择已加载区块。历史全息图区块监听也改为比较世界和区块坐标，避免 `Location.getChunk()` 在刷新时同步加载其他区块。

应完整停服后替换核心再启动，使旧实例的区块票退出；不以热加载作为验收方法。需用相同地图和玩家条件重新采集报告，确认无人在线时区块数停止持续上升、MSPT 回落。当前补丁经过自动化验证，未在该 Leaf 实服验证，不能承诺固定 TPS 数值。

## 玩家档案解析

`IOException encountered while parsing` 的根因是 `PlayerProfile["renown"]` 的 setter 在 MongoJack 异步反序列化时触发了同步 `PitGainRenownEvent`，Paper 因线程错误拒绝该事件。加载历史非零余额被误认为本次新增声望；这条堆栈不表明数据库连接失败或玩家文档损坏。

加载尚未完成时，setter 只恢复余额；运行期奖励先更新余额，再按准确增量在主线程发事件。异步奖励通过主线程任务通知。档案和加载标记使用 `volatile` 发布；读档失败的回调轮询会停止。兼容接口 `waitForLoad()` 不再无限自旋，禁止主线程阻塞，并处理失败、中断及 30 秒超时。解析失败仍沿用原失败处理，不降级创建空白档案。

## NPC 右键

用户版本 FancyNpcs 的 `PlayerUseUnknownEntityListener` 对除盔甲架外的实体跳过带相对坐标的 `INTERACT_AT` 包。核心此前只监听 Fancy 的后续交互事件，因此这类单独到达的右键不能进入菜单事件。报告中同时安装了 ViaVersion/ViaBackwards，但没有客户端抓包，不能据此确认用户每一次右键失败都由协议转换引起。

补丁只对当前 NPC 库注册的实体补充主手 `INTERACT_AT` 转发，进入 Fancy 原有 `interact(player, RIGHT_CLICK)`，继续使用其冷却和可取消的 `NpcInteractEvent`。常规 `INTERACT`、左键、副手和其他插件的实体保留原路径。核心再检查玩家在线、存活、同世界、NPC 实际可见、距离以及实体 ID 注册状态；同一轮右键的两个包只派发一次菜单事件。

## 重复 UUID 的处理边界

`Entity uuid already exists` 表示服务端索引已有相同 UUID，拒绝加入另一个实体。日志中的鸡、猪、狐、牛分布在相邻区块；这与 Fancy 的纯数据包菜单 NPC 属于不同实体路径。目标 Paper/Moonrise 字节码显示，UUID 冲突检查发生在实体进入索引时，普通的实体加入事件无法在这一步之前修复存档。spark 默认配置中的 `duplicate-uuid.mode` 已是 `SAFE_REGEN`；没有简单把该选项再设一次或屏蔽日志。

禁生物生成与移除无限区块票能减少新增实体和无界加载负担，不能消除已经写入世界的重复记录。当前没有用户 world 副本，尚不能判定是重复保存、旧地图转换还是该 Leaf 版本的实体加载问题；没有删除已有实体、改写实体 UUID 或修改地图 NBT。

提供 `scripts/scan_entity_uuids.py`，用 Python 3.10+ 标准库只读扫描停服后的世界副本：

```powershell
python scripts/scan_entity_uuids.py 'D:/MinecraftTest/world-copy' > 'D:/MinecraftTest/entity-uuid-report.json'
```

扫描现代 `entities/*.mca`、旧 `region/*.mca` 中的 `Level.Entities`、乘客和外部 `.mcc`，兼容新旧 UUID 表达及 gzip/zlib/未压缩记录。报告列出重复 UUID、类型、位置、文件与区块；不输出背包或完整实体 NBT。损坏、LZ4 等不支持格式或没有 region 文件时明确标记为不完整，并返回退出码 2；没有重复实体不等于世界数据已被完整验证。旧存储与新存储同时保留的 UUID 重复也需要结合实际加载路径判断，不能直接据此批量清理。

扫描工具没有写入世界的功能。后续应根据副本中的重复记录以及对应 Leaf 版本复现结果，决定存档修复方案。

## 验证

新增 Java 回归覆盖真实 MongoJack codec 的非零声望解码与字段顺序、运行期奖励增量和主线程通知、失败等待终止、NPC 两种右键合并、副手/其他实体排除、区块票回归以及全息图无隐式区块加载。Fancy 兼容任务同时包含显示和点击适配测试，使用用户实际版本再次执行。

扫描工具另有 4 项独立回归，覆盖现代/旧存档重复、乘客、外部文件、损坏与不支持格式，以及扫描前后文件哈希一致。GitHub Actions 已加入该组测试。最终统计、产物大小与校验值见 [迁移报告](HIGH-MIGRATION.md)。
